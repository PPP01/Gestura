# Blacklist with port and path — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a blacklist entry name a port and a path — `localhost:3000`,
`localhost:3001/galaxy-patrol.html` — so one page can lose its gestures without
taking the whole host with it.

**Architecture:** One new classic script, `js/blacklist-match.js`, owns the rule
and every state decision that can be expressed as a pure function; the four places
that today each carry `blacklist.includes(hostname)` call it instead. In
`js/content.js` the verdict splits in two: host and port stay **attach
conditions**, decided once per document as they are today, while the path is
decided on every event through a **live gate** added to `EventManager` — whose
existing conditions are read only in `update()` and never see an event. That is
what lets the rule follow a single-page app's routing in both directions without a
navigation listener and without patching the page's `history` object.

**Tech Stack:** Plain ES2020 in classic scripts (no bundler, no transpiler — the
repo root *is* the unpacked extension), Lit 3 for the components, vitest for tests.

**Spec:** [`docs/superpowers/specs/2026-09-14-blacklist-port-path-design.md`](../specs/2026-09-14-blacklist-port-path-design.md)

## Global Constraints

- **Indentation is tabs**, throughout. Every file in this repo.
- **Nothing compiles.** No build step, no new dependency the extension needs at
  runtime. `package.json` exists for vitest and the Firefox tooling only.
- **Content scripts cannot use ES modules.** `js/blacklist-match.js` is a classic
  script that hangs its API on the global, exactly like `js/menu-patterns.js`.
- **Never put an undeclared `$WORD$` in a message string.** `chrome.i18n` reads it
  as a placeholder and the extension then fails to load *entirely*. Use `{token}`
  plus `.replace()`. `tests/locale-placeholders.test.mjs` guards this.
- **Internal `FlowMouse*` identifiers stay.** The rebrand is user-facing only;
  renaming them would make upstream rebases expensive. New globals get the
  `Gestura*` prefix.
- **Do not touch `manifest.json`'s `version_name`.** It is generated by a git
  clean filter and re-stamped by hooks. Only the numeric `version` is ever edited,
  and not in this plan.
- **Run the suite with `npm test`** (vitest, 39 test files as of this branch's baseline). A single file:
  `npx vitest run tests/blacklist-match.test.mjs`.

### Task 1: The entry parser — `parse` and `normalize`

Turns whatever the user types into the one canonical string the rest of the
feature compares against. The central trap lives here: parsing under `https://`
makes the URL API *delete* a port that is that scheme's default, so
`example.com:443` would silently become the host-wide entry `example.com`. Parsing
under a **non-special** scheme avoids it, because the URL standard gives those no
default port to delete.

**Files:**
- Create: `js/blacklist-match.js`
- Test: `tests/blacklist-match.test.mjs`

**Interfaces:**
- Consumes: nothing.
- Produces: global `GesturaBlacklist` with
  `parse(entry) -> { host: string, port: string, path: string } | null` and
  `normalize(input) -> string | null`. `port` and `path` are `''` when absent.
  `path` always begins with `/` when present and never ends with one.

Create `js/blacklist-match.js`:

```js
// The blacklist rule, in one place. Four callers used to carry their own
// blacklist.includes(hostname): the gesture gate in js/content.js, the popup
// switch, and the context menu's state and its toggle. Four exact-string
// comparisons were four correct implementations of the same thing; four prefix
// matchers would have been four chances to drift.
//
// Design: docs/superpowers/specs/2026-09-14-blacklist-port-path-design.md
(function (root) {
	const SCHEME = /^[a-zA-Z][a-zA-Z0-9+.-]*:\/\//;

	// The port a URL really speaks on. new URL() leaves .port empty when it is the
	// scheme's default, so an entry naming 443 has to be compared against this and
	// not against .port, or it would never match anything.
	function effectivePort(port, protocol) {
		if (port) return port;
		if (protocol === 'https:') return '443';
		if (protocol === 'http:') return '80';
		return '';
	}

	// Parsed under a non-special scheme on purpose. The URL standard gives those no
	// default port, so ':443' and ':80' survive; under 'https://' they are removed
	// and the entry silently widens to the whole host. A non-special scheme also
	// leaves hostname unfolded — hence the explicit toLowerCase — and leaves the
	// path's case alone, which is what we want: hosts are case-insensitive, paths
	// are not.
	function parse(entry) {
		const s = String(entry == null ? '' : entry).trim().replace(SCHEME, '');
		if (!s) return null;
		let u;
		try { u = new URL('gestura://' + s); } catch { return null; }
		const host = u.hostname.toLowerCase();
		if (!host) return null;
		return { host, port: u.port || '', path: u.pathname.replace(/\/+$/, '') };
	}

	function normalize(input) {
		const p = parse(input);
		if (!p) return null;
		return p.host + (p.port ? ':' + p.port : '') + p.path;
	}

	const api = { parse, normalize, effectivePort };
	if (typeof module !== 'undefined' && module.exports) module.exports = api;
	root.GesturaBlacklist = api;
})(typeof self !== 'undefined' ? self : globalThis);
```

In `js/blacklist-match.js`, insert these four functions after `normalize` and

```js
	// The boundary is the path separator, which is why the rule needs no wildcard
	// syntax: /games covers /games/pong and stops short of /gameszone. Compared
	// case-sensitively, because paths are.
	function pathMatches(pathname, path) {
		if (!path) return true;
		if (pathname === path) return true;
		return pathname.startsWith(path + '/');
	}

	function matches(url, entry) {
		const e = parse(entry);
		if (!e) return false;
		let u;
		try { u = new URL(url); } catch { return false; }
		if (u.hostname.toLowerCase() !== e.host) return false;
		if (e.port && effectivePort(u.port, u.protocol) !== e.port) return false;
		return pathMatches(u.pathname, e.path);
	}

	// Every match, not the first: the quick toggle may only act when the bare host
	// is the sole reason a page is blocked, and asking "which one wins" would make
	// that depend on the order entries were added in.
	function matchingEntries(url, entries) {
		if (!Array.isArray(entries)) return [];
		return entries.filter(entry => matches(url, entry));
	}

	// The document-level verdict, split the way js/content.js needs it: host and
	// port are fixed for the life of a document and decided here, once; a path can
	// change under a single-page app, so its entries are only collected here and
	// re-checked per gesture. Pure, so it can be tested without a DOM.
	function evaluate(loc, entries) {
		const result = { originBlocked: false, pathEntries: [] };
		if (!Array.isArray(entries)) return result;

		const host = String(loc.hostname || '').toLowerCase();
		const port = effectivePort(loc.port, loc.protocol);

		for (const raw of entries) {
			const e = parse(raw);
			if (!e || e.host !== host) continue;
			if (e.port && e.port !== port) continue;
			if (e.path) result.pathEntries.push(e);
			else result.originBlocked = true;
		}

		// A frame inside a blocked page is blocked too. An origin has no path, so
		// only host and port entries can decide this one — see issue #7.
		if (!result.originBlocked && loc.ancestorOrigin) {
			let a = null;
			try { a = new URL(loc.ancestorOrigin); } catch { a = null; }
			if (a) {
				result.originBlocked = entries.some(raw => {
					const e = parse(raw);
					if (!e || e.path) return false;
					if (a.hostname.toLowerCase() !== e.host) return false;
					return !e.port || effectivePort(a.port, a.protocol) === e.port;
				});
			}
		}
		return result;
	}
```

### Task 5: A condition that is re-read on every event

`EventManager` has one kind of condition, and it is not the kind this feature
needs. `add(condition, …)` stores it; `update()` (`js/content.js:233`) reads it to
decide whether to **attach** the listener; the registered `safeHandler` (`:215`)
checks `e.isTrusted` and calls straight through. `update()` runs from exactly one
place, `loadSettings()` (`:2403`).

So a condition never sees an event. Without the change in this task, a path entry
would do nothing in either direction: a page entered on an allowed path keeps its
listeners after routing onto a blocked one, and a page entered on a blocked path
never gets them back.

**Files:**
- Modify: `js/content.js:201-221` (the `EventManager` constructor and `add`)

**Interfaces:**
- Consumes: nothing.
- Produces: `eventManager.setLiveGate(fn)` — `fn` is called with no arguments
  before every gated handler; a falsy return drops the event. Applies **only** to
  bindings registered with a non-null `condition`.

- [ ] **Step 1: Add the field to the constructor**

In `js/content.js`, in the `EventManager` constructor (`:202-206`), after

## Done when

- `npm test` passes, with `tests/blacklist-match.test.mjs` among the suites.
- `localhost:3000` blocks that port and leaves `localhost:3001` alone.
- `localhost:3001/galaxy-patrol.html` blocks that page and leaves the rest of the
  port alone — including area selection on the blocked page.
- Routing into and out of a blocked path in an SPA turns gestures off and on again
  without a reload.
- A wheel, rocker or pending area-select left behind by that crossing does not
  come back with it: the next right-click opens the page's own context menu, and
  no selection rectangle appears from the old modifier press.
- Removing the entry restores gestures without a reload.
- `pauseGesture` survives a later blacklist edit.
- The quick toggle is disabled — and *looks* disabled — and names the finer entry
  when something other than the bare host is blocking the page.
- An existing bare-hostname entry behaves exactly as it did before.

- A quick toggle that can choose page, port or domain — [#8](https://github.com/PPP01/Gestura/issues/8).
- Wildcards of any kind.
- The Firefox `background.scripts` list: it lives on `firefox-build` and is added
